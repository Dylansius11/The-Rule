# Wallet-signed browser E2E

**Sandbox with mock OutLayer, not testnet evidence.** This suite never signs against testnet or mainnet.

## Run

From this checkout on Windows:

```sh
pnpm --dir apps/web e2e:sandbox
```

Prerequisites: installed workspace dependencies and Playwright Chromium, working WSL2, the repository's Rust/cargo-near toolchain inside WSL, and at least 20 GiB free on C:. No wallet extension, login, faucet, public account or public RPC is needed. Port **5193** must be free; the normal worktree server on 5183 is untouched. The existing desktop/mobile Playwright projects retain their normal mode and server reuse behavior; they do not collect sandbox specs.

The launcher supplies `E2E_SANDBOX=1`, `E2E_PORT=5193` and a separate OS-temporary Playwright output directory. `globalSetup` starts `scripts/e2e/sandbox.sh` through `wsl.exe -e bash -lc`, quoting the checkout path (including `HP Victus`). It rebuilds this checkout's game/token/mock using the existing sandbox artifact recipe, reuses `$HOME/target-the-rule`, snapshots the resulting wasm outside the repository, and runs the `sandbox-tests` Rust example `web-e2e` with `--profile fast`. These are local non-reproducible **sandbox** artifacts, not deployment artifacts.

The Rust example is deliberately used instead of a second JavaScript deployment harness: it reuses near-workspaces, the existing demo parameters and the real `rule-core` evaluator/equivalence/commitment functions. The mock's yield/resume interface is real; the mock does not execute the enclave program. A preselected even-number law makes the fixture deterministic. The fixture has a one-NEAR seeded Solo pot, 25/50 base attempts, the existing sandbox fee/storage values, a one-hour investigation and a three-second reveal window. Two funded native accounts start with no game credit and no pre-minted RULE. The Solo round starts during setup; Team starts only after the test has checked the no-round explanation. The harness acts as the permissionless local keeper for finalization and season indexing.

## Windows ↔ WSL2

The sandbox chooses an ephemeral RPC port bound inside WSL. Windows reaches its `127.0.0.1` RPC through **WSL2 localhost forwarding**. Setup calls `/status` from Windows and requires the near-workspaces-generated `test-chain-…` chain id before permitting a signer (never `testnet` or `mainnet`). If forwarding is disabled, enable `localhostForwarding=true` in the user's WSL2 configuration and restart WSL manually; the suite fails rather than substituting a public RPC. A Windows loopback-only HTTP proxy adds the browser CORS header and exposes a private mock-control endpoint. The browser receives only that local proxy URL, game/token ids and the test account's public id; neither fallback RPC is available in e2e mode. The contract's `chain_id: "testnet"` is only its commit-preimage domain, matching the existing sandbox fixture; it does not select a public network.

Fixture keys/configuration are generated only for the disposable node and written to `apps/web/e2e/support/.env.sandbox.json` (ignored by the existing `.env.*` rule). They are never embedded in app source, printed, or committed. Global teardown closes the proxy and harness stdin; dropping the near-workspaces Worker stops the node and removes its home. The shell removes its temporary wasm snapshot, and Node removes logs and the generated key file. The command returns nonzero on a startup error or failed assertion. Startup allows twenty minutes for a cold Rust dependency build; cached runs still create a completely fresh chain.

## Signing seam and production isolation

`src/config/env.ts` reads `__THE_RULE_E2E__` only when the compile-time expression `import.meta.env.MODE === 'e2e'` is true. E2E mode fails closed without injection. The only chain change is an early return from `getConnector()` to the injected connector. `addInitScript` supplies a keyless NEAR Connect-shaped bridge; `exposeFunction` sends its requested function calls to the Playwright Node process. There, near-api-js 7 signs with the disposable account's actual full-access key and submits to the verified loopback sandbox. Only the fixture's game/token receivers and function-call actions are accepted. The bridge waits for the actual root action receipt and for its block to become final, and supplies that receipt's exact success/failure status with the observed transaction and receipt data. It does not wait for the deliberately yielded mock descendant, because the test must first observe pending before authorizing its resolution. No success response, balance, view or verdict is fabricated by the browser. This final-root-receipt policy is test-wallet behavior, not a claim that every external wallet uses the same finality policy.

The normal app build does not include the signer, fixture code or executable injection hook. Observed normal-build check on 2026-11-09:

```sh
# In apps/web
pnpm exec vite build
# Search executable dist/**/*.js for:
# __THE_RULE_E2E__|__sandboxSign|Sandbox with mock OutLayer|sandbox-connected|E2E mode requires|"sandbox"|'sandbox'
```

The final build succeeded (`built in 2.20s`) and the executable-JavaScript search returned **no matches**. `pnpm exec tsc --noEmit` also passed with no output (14.23 seconds). **Scope:** Vite currently emits source maps (`vite.config.ts`, `sourcemap: true`), so `.js.map` files retain original source, including the inert env hook. This is an executable-code isolation proof, not a claim that debug source maps contain no sandbox strings. Production/source-map policy is unchanged.

## Assertions and limits

The journey exercises the actual browser's soft wallet gate, credit deposit, pending-before-verdict distinction, NO/YES, free contextual duplicate with unchanged credit/log length, forced mock failure with exact credit/attempt restoration, ledger rows, free wasm consistency check, signed commit/reveal, settlement, claim into game credit, and browser wasm replay. Team covers the no-round state, creation, vault funding and a paid shared-line play. Season checks the new HEAD view and browser rendering. Contract views independently check money/log changes rather than trusting success copy.

A duplicate is free only for the same **full context**, including the minute digit and previous-YES line. A different minute is not the same combination. The mock resolutions use the request's recorded context and the shared Rust evaluator, never a parallel TypeScript evaluator.

RULE-lock coverage is conditional in the assignment. The existing sandbox parameters have no lock tiers, and the current browser's LockPanel enables locks only when the latest returned round is `Scheduled`; future slots are not exposed there. The suite does not fake a scheduled view or pre-mint tokens to claim this path works. A future-round selector plus funded registration/earned RULE is required for a genuine browser lock journey; this remains outside this ticket's UI-edit permissions.

This does **not** prove TEE secrecy, OutLayer execution/latency, attestation, creator blindness, wallet-extension approval UX, production artifact reproducibility, public-network RPC behavior or native-payment stalled-callback recovery. The controlled bridge tests the app's connection/action wiring with real signatures, not an external wallet's code. Browser replay proves consistency with the revealed rule and commitment, not pre-reveal secrecy. No sandbox run is testnet evidence.
