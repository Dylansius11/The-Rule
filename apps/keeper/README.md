# Keeper

**Status:** locally exercised with mock RPC; not ready for a deployed game until the agreed keeper views and opening fields land in the game contract. No testnet transaction or sandbox dry-run has been exercised.

Node >=22.22.2. Install the workspace dependencies with pnpm, then run `pnpm --dir apps/keeper start -- --dry-run`. Set `NEAR_RPC_URL` and `GAME_ACCOUNT`; non-dry runs additionally need `KEEPER_ACCOUNT`, `KEEPER_PRIVATE_KEY`, and `HEALTHCHECK_PING_URL` in the operator's secret store. Do not commit values. Deploying or running against testnet requires the founder's authorization. A dry run reads final views and prints decisions, but neither signs nor pings.

Each run reads a final block timestamp, `get_params`, `get_round` and `get_next_slot` for both modes, and `get_active_rounds`. It processes all due transitions sequentially, including an older Opening round overlapping a newer round of the same mode. A missed slot is due at or after its `slot_ns` unless that mode has a round in Scheduled through Reveal. The heartbeat is sent only if every view succeeded and every attempted transaction returned `FINAL` and a success status, including when nothing was due. A raced E10/E50 is logged and at most one round view is re-read per run, but the race suppresses the heartbeat; other failures also suppress it. The heartbeat reports a successful keeper check, not timely game progress. No SDK nonce or RPC retries are configured. Repeated ticks are independent. Logs omit error details, the key and the heartbeat URL. The signer key should be low-funded and scoped to these methods.

## Contract interface gate

The agreed `RoundView` and keeper views are specified in SMART-CONTRACT. [U] `opening_started_ns`, `open_status`, `rule` and `salt` have not yet landed in the game contract; the other newly agreed fields and views are also in progress. Sealing timeout is measured from `sealing_started_ns`, investigation from `investigation_end_ns`, and opening timeout from `opening_started_ns`. `get_active_rounds` is the authority for identifying all overlapping active rounds; `get_next_slot` is the authority for each next slot. All nanosecond values must survive JSON number precision; the parser preserves large JSON integer literals as decimal strings. Amounts such as `pot` are u128 decimal strings.
