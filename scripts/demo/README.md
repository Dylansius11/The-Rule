## Prepare and reset

1. Prepare real, reviewed game and token WASM using the reproducible contract recipe in `scripts/deploy/README.md`. Use fresh accounts `demo-game.therule.testnet` and `demo-token.therule.testnet`, or matching numbered pairs such as `demo-game-r1.therule.testnet` and `demo-token-r1.therule.testnet`. Never upgrade r2 or reset an initialized game in place. A reset is another **fresh pair**, fresh game/token state, new funding, and a newly caller-bound referee; it is not a deletion or a key ceremony.
2. From the repo root in WSL, use a reviewed immutable workspace snapshot and capture each build's stdout separately. Production remains the default and must be built separately; do not publish or use its bytes as the Demo artifact:

   ```sh
   RULE_GAME_ACCOUNT=demo-game-r1.therule.testnet scripts/referee/build-reproducible.sh SNAPSHOT scratch/deploy/demo-referee.wasm demo | tee scratch/deploy/demo-referee-build.log
   ```

   Independently reproduce the build, validate the component and imports, inspect its caller-bound manifest, and record source revision and both hashes before publication. The build passes no `RULE_DEMO` value into Docker. The build log records snapshot path, caller, feature and SHA-256; it is not a cryptographic source attestation. Inspect the snapshot and record its revision separately. Never capture a rule in build logs.
3. Copy `scripts/deploy/example.json` to a private working config under `scratch/deploy/`. Set `deployment_kind` to `demo`, `demo` to `true`, the matching account pair, `params.token`, artifact paths, demo referee hash and single-build log, URLs, real quotes, funding and compressed schedule. Set `params.referee.demo_secrets_ref` to the public reference `{"profile":"demo","account_id":"therule.testnet"}` with the actual chosen profile and testnet owner. This is not the selected rule. Rehearsal must omit it or set it to null. Never put `RULE_DEMO`, rule JSON or a secret value in this config, a URL, contract args, a plan, shell history, logs, chat or public artifacts.
4. Generate and inspect the offline plan with `python3 scripts/demo/prepare.py scratch/deploy/demo-config.json`. The shared planner writes `scratch/deploy/plan.json` and `commands.sh` and verifies artifact kind, embedded caller, account pairing and schedule. These output paths are shared with rehearsal: copy reviewed outputs aside before planning the other instance. No network call, signature or transaction is made by this entrypoint. As with rehearsal, generated commands are not authorization. The generic planner's `--execute` is separately gated and must not be used until the secret-routing prerequisite and all deployment checks are met.
5. Once separately authorized and the prerequisite is resolved, create/fund the new pair, publish and verify exact referee bytes, set up the secret, deploy the planned real contracts, verify on-chain hashes and params, fund compute/operator collateral, and operate a real round. Quote live token storage, permanent operation funding and OutLayer costs as in the deployment guide. Record actual receipts and replay; do not call a planned or local run testnet evidence.

## Rule and secret routing prerequisite

The selected value is a single canonical `rule-core::CanonicalRule` JSON object, not a contract argument. The guest parses it with the shared parser and requires `rule_core::classify` to accept it; syntactically valid but unfair rules fail. Choose and validate privately using the real guest/shared code, not a second evaluator. The environment variable name is `RULE_DEMO`. The creator knows this rule. Never reuse its value in production.

OutLayer's [Secrets documentation](https://app.outlayer.ai/docs/secrets#secrets-binding) describes a manual encrypted row bound to a **WASM SHA-256**, profile and owner, suitable for direct `WasmUrl` runs; the [NEAR integration schema](https://app.outlayer.ai/docs/near-integration#request-execution) requires `secrets_ref: {"profile": ..., "account_id": ...}` to name that row. The [manifest specification](https://raw.githubusercontent.com/out-layer/outlayer/main/wasi-examples/CONNECTOR_MANIFEST.md) says project `author_secrets` are unavailable to direct WasmUrl runs. Hash binding is not the same as the referee's separate `encryption_keys` MAC binding to code and predecessor. Configure the secret's access condition for the actual transaction signer(s), additionally restricted to the Demo game predecessor where supported; check the [access rules](https://app.outlayer.ai/docs/secrets#access-control) and testnet availability before any funded run. Do not grant unintended callers.

The game passes its immutable `demo_secrets_ref` as the top-level `secrets_ref` on all four operations; use the new artifact, not r2, which sends null. After fresh authorization, configure a hash-bound manual row using either the testnet [OutLayer Secrets UI](https://app.outlayer.ai/secrets) or the reviewed official CLI encryption format. D37 used in-memory X25519/HKDF-SHA256/ChaCha20-Poly1305 encryption and an isolated parent signer because the browser wallet bridge stalled. Only the public accessor, profile, restricted Demo predecessor condition and ciphertext entered `store_secrets`; plaintext never entered command arguments, logs or public inputs. Its owner/profile were `therule.testnet` / `the-rule-demo`. Actual begin, verdict, guess and open receipts—not configuration alone—proved routing. See the official [crypto implementation](https://github.com/out-layer/outlayer-cli/blob/main/src/crypto.rs). A reset needs a newly caller-bound build, hash-bound row and fresh authorization. Never switch to Project source or expose the rule through public input to bypass failures.
